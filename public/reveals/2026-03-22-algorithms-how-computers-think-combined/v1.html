// Section 01

What IS an Algorithm?

A word that sounds intimidating but describes something you already do every single morning.

~8 min section. Start with definition, then analogies, then real examples.
// Definition

Algorithm = Step-by-Step Recipe

An algorithm is a precise set of instructions for solving a problem — written so clearly that even a computer (or a very literal robot) can follow them.

  It Must Be

  • Finite — it ends eventually
  • Unambiguous — no guesswork allowed
  • Effective — actually solves the problem

  NOT an Algorithm

  • "Make it work better" — too vague
  • "Try your best" — computers can't try
  • "Figure it out" — not a set of steps
Emphasize "unambiguous" — this is the huge insight. Computers are incredibly literal. They only know exactly what you tell them.
// Analogy

Think of It Like Making a PB&J

You'd say:

"Spread peanut butter on bread, then add jelly, then close it."

— A normal human instruction

A computer needs:

  1. Pick up knife

  2. Open peanut butter jar

  3. Dip knife into peanut butter (exactly 2cm)

  4. Spread on top face of bread slice #1

  The Big Idea

Computers are incredibly dumb — but also incredibly incredibly fast. Your job as a programmer is to give them smart instructions.

  Why This Matters

A good algorithm can solve in seconds what would take a human years. The instructions are everything.

Great place for audience interaction! Ask: "What step did I miss in the PB&J?" This usually gets laughs and drives home the point.
// Types

There Are Many Kinds of Algorithms

  Searching

Find something specific in a pile of data. Used in Google, Spotify, your camera's face detection.

  Sorting

Organize messy data into order. Used every time you scroll a list, view your photos, or rank results.

  Pathfinding

Find the shortest or best route. Used in Google Maps, video game AI, logistics routing.

  Machine Learning

Algorithms that learn from data and improve on their own. Used in ChatGPT, image recognition, recommendations.

Don't go deep on ML here — just plant the seed. The first two (search/sort) are what we'll dig into today.

// Relatable Algorithm

Your Morning Routine = Algorithm

  1. Alarm goes off → wake up (or snooze?)

  2. IF late → skip breakfast, grab a bar

  3. ELSE → cereal or eggs?

  4. Check weather → pick outfit

  5. Grab bag, check for keys, leave

Notice the IF / ELSE decision? That's exactly how code works. Conditional logic is the foundation of all algorithms.

  In Code Terms

if (late) { skipBreakfast() }
else { makeBreakfast() }

Ask the room: "Who has a morning routine?" Then: "You just described an algorithm." Watch the light bulbs turn on.

// Loops

Repetition = Loops

A loop is just: "Keep doing this until the condition is met." You do this all the time.

  • Scrolling Instagram until you get bored
  • Trying outfit after outfit until it "looks right"
  • Refreshing the game until you get the drop you want
// Scroll until bored while (!bored) { scrollFeed(); likePost(); checkBoredom(); } // Try outfits for (let i = 0; i < closet.length; i++) { if (looksGood(closet[i])) { break; // found it! } }
The "scroll until bored" example usually kills. Point out that TikTok's recommendation engine is literally a loop that runs thousands of times per second to figure out what video to show you next.

Searching: Finding the Needle

Two classic algorithms — and a dramatic difference in how fast they work.

// Algorithm 1

Linear Search — Check Every Single One

Looking for your AirPod case in your room = Linear Search.

  1. Look at item #1. Is it what I need?

  2. No? Move to item #2.

  3. Keep going until found or exhausted.

✅ Good When...

The list is small, OR it's not sorted, OR you're only searching once.

⚠️ Bad When...

The list has millions of items — you could end up checking ALL of them.

O(n) — Linear Time

// Algorithm 2

Binary Search — Split the Problem in Half

Only works on sorted lists — but it's dramatically faster.

  1. Look at the middle item

  2. Too high? Search the left half only

  3. Too low? Search the right half only

  4. Repeat until found

Like the "higher or lower" number guessing game — you always cut the options in half.

// Comparison

Linear vs Binary: The Numbers

Max number of checks to find something in a list of N items:

List Size Linear Search (worst case) Binary Search (worst case)
10 items 10 checks 4 checks
100 items 100 checks 7 checks
1,000 items 1,000 checks 10 checks
1,000,000 items 1,000,000 checks 20 checks
1,000,000,000 1 billion checks 😰 30 checks 🤯

1 billion items → only 30 checks. That's the power of a well-designed algorithm.

This table always creates gasps. Really let the "1 billion → 30 checks" sink in. Ask: "How is that possible?" — the magic of logarithms (halving repeatedly).

Sorting: Order from Chaos

// Context

Why Sorting Matters So Much

  • Your contacts list — sorted alphabetically
  • Your music library — sorted by artist, album, date
  • Google results — sorted by relevance score
  • TikTok's feed — sorted by predicted engagement
  • E-commerce — sorted by price, rating, recency

  Scale of the Problem

Google processes 8.5 billion searches per day. Each one involves sorting results. Efficient sorting algorithms save millions of dollars in computing costs.

  Fun Fact

Sorting has been studied since the 1940s. Researchers still argue about the best approach for different situations.

Google/TikTok examples resonate immediately with high schoolers. Pause on those.
// Sorting Algorithm 1

Bubble Sort — Simple but Slow

Compare neighbors. Swap if out of order. Repeat.

// Round 1 pass: [5, 3, 8, 1, 4] ↑ ↑ // compare 5,3 → swap! [3, 5, 8, 1, 4] ↑ ↑ // 5,8 → ok [3, 5, 8, 1, 4] ↑ ↑ // 8,1 → swap! [3, 5, 1, 8, 4] ↑ ↑ // 8,4 → swap! [3, 5, 1, 4, 8] ← 8 bubbled up!

✅ Pros

Dead simple to understand and code. Great for learning. Works on tiny lists.

⚠️ Cons

Terribly slow on large lists. For 1,000 items, it could need up to 1,000,000 comparisons.

O(n²) — Quadratic Time
Demo this with 5 volunteers holding numbered cards! Physical sorting demos are incredibly memorable.
// Sorting Algorithm 2

Merge Sort — Divide & Conquer

Split the list in half, sort each half, then merge them back together.

[38, 27, 43, 3]

↙ split ↘

[38, 27]

[43, 3]

↙ ↘

    

↙ ↘

[38]

[27]

[43]

[3]

↓ merge sorted pairs ↓

[27, 38]

[3, 43]

↓ merge ↓

[3, 27, 38, 43] ✅

O(n log n) — Much faster than Bubble Sort!
The key insight: sorting two small halves and merging is much easier than sorting the whole thing at once. This is "divide and conquer" thinking — a huge CS concept.

// Section 05

Big O: How Fast Is Fast?

The universal language for comparing how efficient algorithms are — regardless of computer speed.

~7 min. Keep this conceptual, not mathematical. The goal is intuition, not formulas.
// Big O Notation

Big O = Measuring Efficiency

Big O Notation describes how much longer an algorithm takes as the input gets bigger. It's not about seconds — it's about growth rate.

Think of it like this:

  • A tiny backpack takes 1 second to find anything
  • A wardrobe takes a bit longer
  • A warehouse takes much longer

Big O tells you: how much longer as things scale up?

O(1) — Constant

Always the same time, no matter how big. Looking up your contact by phone number.

O(n) — Linear

Doubles when input doubles. Scrolling through every message in your inbox.

Don't use the word "asymptotic" or any math terminology. Intuition only. The backpack/warehouse analogy works really well for grounding this.
// Complexity Classes

The Big O Lineup — Fastest to Slowest

Notation Name Example 1000 items =
O(1) Constant Access array by index 1 operation
O(log n) Logarithmic Binary search ~10 operations
O(n) Linear Linear search 1,000 operations
O(n log n) Log-linear Merge sort ~10,000 operations
O(n²) Quadratic Bubble sort 1,000,000 operations
O(2ⁿ) Exponential Brute-force passwords More than atoms in universe
The last row (O(2^n)) always makes people say "wait what?" — this is a great moment to mention that this is WHY passwords with more characters are exponentially harder to crack.
// Real Impact

This Isn't Just Theory

  Music Recommendations

Spotify compares your listening history to 500 million+ users. A bad algorithm choice would mean your "Discover Weekly" takes hours to generate.

  GPS Navigation

Google Maps uses Dijkstra's algorithm to find shortest paths in real time across road networks with millions of nodes.

  Password Security

Your 8-character password: 200 billion possible combinations. A computer tries all of them in seconds. That's why complexity matters — O(2ⁿ) saves us.

Choosing the right algorithm can be the difference between a product that works and one that costs a company millions.

The password example is the best one — it immediately connects to something they care about. Ask: "Who uses the same password for everything?" (hands usually go up) — then explain why Big O makes that dangerous.

Algorithms Shape Your World

Every swipe, every scroll, every recommendation — there's an algorithm making that decision.

~5 min. Closing section — bring it back to relevance and inspiration.
// Everywhere

You Interact with Algorithms Hundreds of Times a Day

  TikTok / Instagram

Watches how long you pause on each video. Runs a recommendation algorithm to predict what keeps you watching. Eerily accurate.

  Google Search

PageRank — Google's original algorithm. Ranks pages by how many other trusted pages link to them. Changed the internet.

  Uber / Lyft

Matching algorithm pairs you with a driver in seconds. Dynamic pricing algorithm adjusts cost based on supply/demand in real time.

  Face ID

Your phone maps 30,000+ infrared dots on your face and runs a face-matching algorithm every time you unlock it.

Ask: "Which of these surprised you the most?" The Face ID fact usually wins.
// The Other Side

Algorithms Can Also Go Wrong

  • Bias in hiring — AI trained on historical data that excluded certain groups, then recommended against them
  • Filter bubbles — Social media shows you more of what you already believe, amplifying division
  • Facial recognition errors — Early models had dramatically higher error rates on darker skin tones

"Algorithms are opinions embedded in code."

— Cathy O'Neil, mathematician & author of Weapons of Math Destruction

The people who design algorithms shape how society works. That could be you.

This is a critical thinking moment — especially powerful for high schoolers who are about to enter a world shaped by these systems. Encourage them to question algorithmic decisions they encounter.

  4. Try LeetCode Easy problems when you feel ready
