01

Variables &
Data Types

The atoms of every JS program — and every Vue component

Section intro. Ask: "Who's comfortable with the difference between let, const, and var right now — not in Vue, just in JS?"
Concept → Vue 3
Variables & Data Types

Declarations map directly to reactivity APIs

let = reassignable · const = fixed reference · Know your primitives: string, number, boolean, null, undefined, symbol, bigint

const name = "Nerando"; // string
let score = 42;          // number
let isActive = true;     // boolean
const user = { id: 1 }; // object
const tags = ["vue"];    // array
● Vue 3 — ref() & reactive()
import { ref, reactive } from 'vue'

// ref wraps primitives
const name = ref("Nerando")
const score = ref(42)
const isActive = ref(true)

// reactive wraps objects
const user = reactive({
  id: 1,
  role: "developer"
})
// .value for ref, direct for reactive
console.log(name.value) // "Nerando"
console.log(user.role)  // "developer"
Key insight: "ref() under the hood is just a JS object with a .value property and a getter/setter. It's not magic — it's a class instance." If you know object property descriptors, you already understand ref().
02

Template
Literals

Backticks that power your bindings

Concept → Vue 3
Template Literals

Embedded expressions — used daily in Vue bindings

Backticks (`) embed expressions: `Hello, ${name}!`. Multiline, expression-aware, composable.

const role = "developer"
const msg = `Hello, ${name}!
You are a ${role}.`

// Expression inside
const total =
  `$${(qty * 9.99).toFixed(2)}`
● Vue 3 usage
// Computed string
const greeting = computed(() =>
  `Welcome back, ${user.name}!`
)

// Dynamic :class binding
// in template
// :class="`btn ${isActive
//   ? 'btn--active'
//   : 'btn--idle'}`"

// Dynamic route path
const path = computed(() =>
  `/users/${userId.value}/profile`
)
Template literals are so common in Vue that devs often use them without realizing it's a core JS feature. Point out the :class binding pattern — this trips up beginners constantly.
03

Arrow
Functions

The backbone of the Composition API

Arrow functions are everywhere in Vue 3 Composition API. If someone is still defaulting to function() inside computed(), they're working harder than needed.
Concept → Vue 3
Arrow Functions

Concise syntax + lexical this — critical for Composition API

// Traditional
function add(a, b) { return a+b }

// Arrow — implicit return
const add = (a, b) => a + b

// Arrow with body
const greet = (name) => {
  return `Hello, ${name}`
}

// In array methods
const evens =
  [1,2,3,4].filter(n => n%2===0)
● Vue 3 Composition API
const count = ref(0)

// computed uses arrow callback
const doubled = computed(
  () => count.value * 2
)

// watch uses arrow callback
watch(count, (newVal, oldVal) => {
  console.log(`${oldVal} → ${newVal}`)
})

// event handler in <script setup>
const handleClick = () => {
  count.value++
}
The "lexical this" point is critical for Options API migrants. In Composition API this isn't used at all — which is why arrow functions fit so naturally. Mention this if the audience has Vue 2 background.
04

Objects &
Destructuring

How composables return values to you

Concept → Vue 3
Objects & Destructuring

Extract exactly what you need — composables depend on this

const user = {
  name: "Nerando",
  role: "dev",
  city: "Atlanta"
}
// Destructure
const { name, role } = user
// Rename
const { name: devName } = user
// Default value
const { theme = "dark" } = user
// Array destructure
const [first,,third] = ["a","b","c"]
● Vue 3 — composable returns
// defineProps destructuring
const { title, count } =
  defineProps(['title', 'count'])

// Composable return destructure
const { data, error, pending } =
  useFetch('/api/users')

// Route params
const { params, query } = useRoute()

// Pinia store destructure
// (use storeToRefs to keep reactivity!)
const { user, isAuth } =
  storeToRefs(useAuthStore())

Vue 3 gotcha: destructuring a reactive() object breaks reactivity — use toRefs() or storeToRefs()

The storeToRefs gotcha is a real pain point. If you have time, live-demo breaking reactivity by destructuring reactive() directly, then fixing it with toRefs(). Audience members who've hit this will immediately recognize it.

05

Arrays &
Array Methods

.map() .filter() .reduce() — your v-for fuel

Concept → Vue 3
Arrays & Array Methods

Data transformation — the engine behind v-for

const nums = [1, 2, 3, 4, 5]

// transform each item
const doubled =
  nums.map(n => n * 2)
// [2, 4, 6, 8, 10]

// keep matching items
const evens =
  nums.filter(n => n % 2 === 0)
// [2, 4]

// accumulate
const sum =
  nums.reduce((acc,n) => acc+n, 0)
// 15
● Vue 3 — v-for + computed
<!-- template -->
<li
  v-for="item in activeItems"
  :key="item.id"
>
  {{ item.name }}
</li>

<!-- script setup -->
<script setup>
const items = ref([...])

const activeItems = computed(() =>
  items.value
    .filter(i => i.active)
    .sort((a, b) =>
      a.name.localeCompare(b.name))
)
</script>
Emphasize: computed + array methods is one of the most common Vue 3 patterns in the wild. If they're mutating arrays directly in templates, that's a red flag. Filter in computed, iterate in v-for.
06

Promises &
Async/Await

onMounted, useAsyncData, and every API call you'll ever write

Concept → Vue 3
Promises & Async/Await

Async operations — the foundation of data fetching in Vue

// Promise chain
fetch('/api/user')
  .then(r => r.json())
  .then(d => console.log(d))
  .catch(e => console.error(e))

// async/await — cleaner
async function getUser() {
  try {
    const res = await fetch('/api/user')
    return await res.json()
  } catch (err) {
    console.error('Failed:', err)
  }
}
● Vue 3 — onMounted + async
const data = ref(null)
const error = ref(null)
const loading = ref(false)

onMounted(async () => {
  loading.value = true
  try {
    const res = await fetch('/api/data')
    data.value = await res.json()
  } catch (e) {
    error.value = e.message
  } finally {
    loading.value = false
  }
})

Nuxt users: useAsyncData() and useFetch() are built on this exact pattern

This is where most Vue 3 bugs live. Ask: "Who's used async inside a computed and wondered why it didn't work?" — computed cannot be async in Vue 3. That's a JS + Vue constraint worth calling out explicitly.
07

Modules &
Exports

Every composable is a module. Every import is this.

Concept → Vue 3
Modules & Exports

ES Modules → Composables

// math.js — named exports
export const add = (a, b) => a + b
export const PI = 3.14159

// user.js — default export
export default function createUser(n) {
  return { name: n, active: true }
}

// app.js
import createUser from './user.js'
import { add } from './math.js'
● Vue 3 — composables as modules
// composables/useCounter.js
import { ref } from 'vue'

export function useCounter(initial = 0) {
  const count = ref(initial)
  const inc = () => count.value++
  const dec = () => count.value--
  const reset = () =>
    count.value = initial

  return { count, inc, dec, reset }
}

// MyComponent.vue <script setup>
import { useCounter }
  from '@/composables/useCounter'

const { count, inc } = useCounter(10)
Composables ARE the module pattern. If they understand import/export, they already understand composables structurally. The only Vue-specific part is that the functions inside can use Vue's reactivity APIs.
08

Classes &
OOP

Blueprints for custom directives & plugins

Concept → Vue 3
Classes & OOP

Useful for Vue plugins, directives & complex state models

class ApiClient {
  constructor(baseURL) {
    this.baseURL = baseURL
    this.headers = {
      'Content-Type': 'application/json'
    }
  }

  async get(path) {
    const res = await fetch(
      `${this.baseURL}${path}`,
      { headers: this.headers }
    )
    return res.json()
  }
}
● Vue 3 — Plugin pattern
// plugins/apiClient.js
class ApiClient { /* ... */ }

export default {
  install(app, options) {
    const client =
      new ApiClient(options.baseURL)

    // Available via inject()
    app.provide('api', client)

    // Or as global property
    app.config.globalProperties.$api =
      client
  }
}
// main.js
app.use(ApiClientPlugin, {
  baseURL: 'https://api.example.com'
})
Most Vue 3 devs rarely write classes directly — but they interact with class-based APIs constantly (Pinia, Vue Router internals, plugins). Understanding OOP helps you read library source code and write robust plugins.
09

Optional
Chaining

Navigate API responses safely — every time

Concept → Vue 3
Optional Chaining & Nullish Coalescing

Safe access — most adopted JS feature in State of JS 2024

// Without optional chaining
const city =
  user && user.address
    ? user.address.city
    : undefined

// With optional chaining ✨
const city = user?.address?.city

// Call functions safely
const str = name?.toUpperCase()

// Nullish coalescing fallback
const display = city ?? "Atlanta"
● Vue 3 — templates & computed
<!-- Template — safe access -->
<p>{{ user?.profile?.bio }}</p>
<p>{{ post?.author?.name ?? 'Anonymous' }}</p>

<!-- Script setup -->
const city = computed(() =>
  store.user?.address?.city ?? 'N/A'
)

// In watch — handle undefined initial
watch(user, (u) => {
  if (u?.isAdmin) enableAdminMenu()
})
State of JS 2024: nullish coalescing (??) was the most adopted JS syntax feature. Your audience is already using this — call it out. Great opportunity to mention that Vue templates support the full JS expression syntax.
10

Event
Handling

@click is just addEventListener with Vue superpowers

Concept → Vue 3
Event Handling

Vue's event system is native JS events + directive sugar

// Native JS
el.addEventListener('click', (e) => {
  console.log(e.target)
  e.preventDefault()
  e.stopPropagation()
})

// Event object properties
// e.target — element clicked
// e.currentTarget — listener element
// e.key — for keyboard events
// e.detail — for custom events
● Vue 3 — v-on / @ directives
<!-- Basic -->
<button @click="handleClick">Go</button>

<!-- .prevent modifier -->
<form @submit.prevent="onSubmit">

<!-- .stop modifier -->
<div @click.stop="doSomething">

<!-- Emit custom events -->
<!-- child component -->
const emit = defineEmits(['update'])
emit('update', { value: 42 })

<!-- parent -->
<Child @update="handleUpdate" />
Vue's event modifiers (.prevent, .stop, .once, .self) are quality-of-life wrappers around native JS event methods. Understanding the native API means you'll know exactly when modifiers aren't enough and you need the event object directly.
11

Error
Handling

Fail gracefully. Your users deserve it.

Concept → Vue 3
Error Handling

try/catch in JS → onErrorCaptured in Vue 3

// Synchronous
try {
  riskyOperation()
} catch (err) {
  console.error(err.message)
} finally {
  cleanup()
}

// Async
async function load() {
  try {
    const data = await fetchData()
    return data
  } catch (err) {
    // Handle fetch errors
    notifyUser(err.message)
  }
}
● Vue 3 — error lifecycle hooks
// In a parent/layout component
onErrorCaptured((err, instance, info) => {
  console.error('Vue caught:', err)
  errorLog.value = {
    message: err.message,
    component: info
  }
  return false // stop propagation
})

// Global handler in main.js
app.config.errorHandler = (err, vm, info) => {
  // Send to Sentry, Datadog, etc.
  trackError(err, info)
}
onErrorCaptured is Vue's equivalent of a try/catch at the component tree level. If they understand try/catch, this is intuitive. Mention app.config.errorHandler for production error tracking — most teams skip this and regret it.
