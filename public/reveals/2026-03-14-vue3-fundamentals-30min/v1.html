Vue in One Slide

Declarative Rendering
Describe what the UI should look like based on your data — not how to update it.

Reactivity
When your data changes, Vue updates the DOM automatically. No getElementById. No manual re-renders.

Component Model
Build UIs as reusable, self-contained pieces — each with its own logic, template, and styles.


<script setup>
import { ref } from 'vue'
const count = ref(0)
</script>

<template>
  <button @click="count++">
    Clicked {{ count }} times
  </button>
</template>
This button example is the entire Vue pitch. No DOM manipulation. Change count, UI updates. That's it.

04 / 16

ref — Reactive State

Vanilla JS — manual


let count = 0
document.getElementById('btn')
  .addEventListener('click', () => {
    count++
    document.getElementById('num')
      .textContent = count
  })

Vue 3 — reactive


<script setup>
import { ref } from 'vue'
const count = ref(0)
</script>

<template>
  <button @click="count++">
    {{ count }}
  </button>
</template>

One rule: use .value in script. Drop it in the template — Vue unwraps automatically.

The left side is the world we're escaping. The right side is what Vue gives you. Same result. A fraction of the code.
05 / 16

Computed Properties

Derive values from existing state — cached, efficient, always in sync.


<script setup>
import { ref, computed } from 'vue'

const firstName = ref('Nerando')
const lastName  = ref('Johnson')

// Only recalculates when firstName or lastName changes
const fullName = computed(() => `${firstName.value} ${lastName.value}`)
</script>

<template>
  <p>{{ fullName }}</p>
</template>

Think of it like a spreadsheet formula — cell A3 automatically reflects changes to A1 and A2.

Computed is one of the most underused tools by beginners. If you find yourself writing a function that just returns a transformed version of some state — that's a computed property.

Components

The Single-File Component


<!-- TaskCard.vue -->

<script setup>
import { ref } from 'vue'
const done = ref(false)
</script>

<template>
  <div :class="{ done }">
    <slot />
    <button @click="done = true">
      Complete
    </button>
  </div>
</template>

<style scoped>
.done { opacity: 0.5; }
</style>

script setup

Logic — reactive state, methods, imports. <script setup> is modern Vue 3 syntax.

template

Your HTML + Vue directives. Everything here reacts to the script.

style scoped

CSS that only applies to this component. No collisions.

07 / 16

Props Down, Events Up

Parent passes data via props ↓


<!-- App.vue -->
<TaskCard
  :title="task.title"
  @complete="markDone"
/>

Child emits events up ↑


<!-- TaskCard.vue -->
<script setup>
defineProps({ title: String })
const emit = defineEmits(['complete'])
</script>

<template>
  <button @click="emit('complete')">
    {{ title }}
  </button>
</template>

This single pattern — props down, events up — governs all component communication.

Template Directives

The special attributes that give your templates superpowers.

08 / 16

The Directives You'll Use Daily

v-bind / :

Bind attribute to a reactive value
:href="url"   :class="{ active }"

v-on / @

Listen for DOM events
@click="fn"   @submit.prevent="fn"

v-model

Two-way binding on inputs
v-model="searchQuery"

v-if / v-else

Conditional rendering
v-if="isLoggedIn"

v-for

Loop over arrays and render a list — always pair with :key
v-for="item in items" :key="item.id"

09 / 16

Directives in Action


<script setup>
import { ref } from 'vue'
const newSkill = ref('')
const skills   = ref(['Vue 3', 'TypeScript', 'Nuxt'])

function add() {
  if (newSkill.value.trim()) {
    skills.value.push(newSkill.value.trim())
    newSkill.value = ''
  }
}
</script>

<template>
  <input v-model="newSkill" @keyup.enter="add" placeholder="Add a skill" />
  <button @click="add">Add</button>

  <ul v-if="skills.length">
    <li v-for="skill in skills" :key="skill">{{ skill }}</li>
  </ul>
  <p v-else>No skills yet.</p>
</template>
v-model, @keyup.enter, @click, v-if, v-else, v-for :key — all five essential directives, one tiny component.
