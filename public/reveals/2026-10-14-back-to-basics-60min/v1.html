Act 1

Data & State

Variables · Template literals · Destructuring

10:00. Ten minutes for Act 1 including Demo 1.

[1]

Variables & Data Types

What is it? Where values live, and whether they're copied or shared.

Primitives vs references is the whole game for reactivity.

[1] Variables & Data Types

How do we do it wrong?

let count = 0
const increment = () => count++
// the template never updates

How do we do it better?

const count = ref(0)
const increment = () => count.value++
// const holds the box, .value changes

Good: Primitives copy. Objects share. ref() wraps your value in an object for a reason.

Ask: why can count be const if it changes? Because the ref object never changes, only its value.

[2]

Template Literals

What is it? Strings with JavaScript expressions inside.

Quick one. The point is the mental model for the template.

[2] Template Literals

How do we do it wrong?

const label = 'Hi ' + first.value +
  ' ' + last.value + '!'
const cls = 'btn btn-' + variant.value

How do we do it better?

const label = computed(
  () => `Hi ${first.value} ${last.value}!`
)
// template: :class="`btn btn-${variant}`"

Good: {{ }} is a JavaScript expression. Same mental model as ${ }.

If you can read a template literal, you can read a Vue template. Note .value in script, none in the template: refs auto-unwrap there.

[4]

Objects & Destructuring

What is it? Pulling values out of objects into their own variables.

This is the opening-hook bug. Build the tension before Demo 1.

[4] Objects & Destructuring

How do we do it wrong?

const state = reactive({ name: 'Ada' })
const { name } = state
// name is a plain string now

How do we do it better?

const state = reactive({ name: 'Ada' })
const { name } = toRefs(state)
name.value = 'Grace' // still reactive

Good: Vue 3.5+: destructured defineProps() stays reactive. reactive() still doesn't.

toRefs turns each property into a ref linked back to the source.

Functions & Transformation

Arrow functions · Array methods

20:00. Eight minutes for Act 2 including Demo 2.

[3]

Arrow Functions

What is it? Short functions with no this of their own.

Most Composition API callbacks are arrows. Here's why.

[3] Arrow Functions

How do we do it wrong?

const doubled = computed(function () {
  return this.count * 2
  // this is undefined in <script setup>
})

How do we do it better?

const doubled = computed(() => count.value * 2)

watch(count, (next, prev) => {
  console.log(prev, '→', next)
})

Good: In <script setup> there is no this. Arrow functions make that obvious.

Options API habits are where this bites. Name the habit, then break it.

[5]

Arrays & Array Methods

What is it? filter, map, reduce: the engine behind every v-for.

Computed lists are just array methods with a cache.

[5] Arrays & Array Methods

How do we do it wrong?

const sorted = computed(() =>
  items.value.sort(byName)
  // sort() mutates the source!
)

How do we do it better?

const visible = computed(() =>
  items.value
    .filter(i => i.active)
    .toSorted(byName)
)

Good: Computed should READ, never mutate. Use toSorted() or [...items].sort().

Mutating inside computed causes loops and warnings. Know which array methods mutate.

Promises · Optional chaining · Error handling

28:00 checkpoint. Ten minutes for Act 3 including Demo 3.

[6]

Promises & Async/Await

What is it? Code that finishes later.

If onMounted feels like guessing, this is why.

[6] Promises & Async/Await

How do we do it wrong?

onMounted(() => {
  weather.value = fetch(url)
    .then(r => r.json())
  // a Promise, not your data
})

How do we do it better?

onMounted(async () => {
  loading.value = true
  const res = await fetch(url)
  weather.value = await res.json()
  loading.value = false
})

Good: Every async UI has three states: loading, data, error.

This version still has a hole. What happens when the fetch fails? That's fundamental 11.

[9]

Optional Chaining

What is it? Ask safely when the data might not be there yet.

The data is null until the fetch lands. The template renders anyway.

[9] Optional Chaining

How do we do it wrong?

<p>{{ weather.current.temp }}°</p>
<!-- TypeError while loading -->

How do we do it better?

<p>{{ weather?.current?.temp ?? '--' }}°</p>
<!-- safe path + a default -->

Good: ?. guards the path. ?? supplies the default. || would hide a real 0°.

The 0 degrees example lands well. Zero is a real temperature.

[11]

Error Handling

What is it? Plan for the API to fail. It will.

Closes the hole from fundamental 6.

[11] Error Handling

How do we do it wrong?

const res = await fetch(url)
weather.value = await res.json()
// bad city → blank screen

How do we do it better?

try {
  const res = await fetch(url)
  if (!res.ok) {
    throw new Error(`HTTP ${res.status}`)
  }
  weather.value = await res.json()
} catch (e) {
  error.value = e.message
} finally {
  loading.value = false
}

Good: fetch only rejects on network failure, so check res.ok. onErrorCaptured catches what bubbles up.

finally means loading always turns off. That's the hole from fundamental [6], two slides back, now closed.

Act 4

Structure & Communication

Modules · Classes · Events

38:00. Seven minutes for Act 4 including Demo 4.

[7]

Modules & Exports

What is it? One file, one job, shared on purpose.

Composables are the payoff.

[7] Modules & Exports

How do we do it wrong?

// WeatherCard.vue, Forecast.vue, Header.vue
onMounted(async () => {
  const res = await fetch(`/api/weather?q=${city}`)
  weather.value = await res.json()
})
// pasted three times, fixed three times

How do we do it better?

// composables/useWeather.js
export function useWeather(city) {
  const weather = ref(null)
  const error = ref(null)
  // fetch + loading + error, once
  return { weather, error }
}

Good: A composable is just a function in a module. No magic.

Named exports for composables. import { useWeather } from '@/composables/useWeather'.

[8]

Classes & OOP

What is it? Blueprints for objects. Useful. Not everywhere.

Keep this one tight. It's the first cut if running long.

[8] Classes & OOP

How do we do it wrong?

class Cart {
  #items = []
  add(i) { this.#items.push(i) }
}
const cart = reactive(new Cart())
cart.add(item) // TypeError: Proxy vs #private

How do we do it better?

class WeatherApi {
  constructor(baseUrl) { this.baseUrl = baseUrl }
  get(city) {
    return fetch(`${this.baseUrl}?q=${city}`)
  }
}
// UI state stays in ref() / reactive()

Good: Classes for services and API clients. Plain objects and refs for component state.

Private fields don't survive a reactive Proxy. Good reason to keep classes at the edges.

[10]

Event Handling

What is it? Listening for what happens, and announcing your own.

DOM events, modifiers, then custom events with defineEmits.

[10] Event Handling

How do we do it wrong?

<div class="btn" @click="save">Save</div>
<!-- no keyboard, no focus, no role -->

How do we do it better?

<form @submit.prevent="save">
  <button type="submit">Save</button>
</form>

<script setup>
const emit = defineEmits(['saved'])
const save = () => emit('saved')
</script>

Good: Native elements bring keyboard and focus for free. defineEmits documents your component's API.

Enter key submits the form for free. The div version needs tabindex, role and key handlers to catch up.

Spot the JavaScript

<script setup>
import { ref, computed } from 'vue'
import { useWeather } from '@/composables/useWeather'
const props = defineProps({ cities: Array })
const emit = defineEmits(['city-selected'])
const query = ref('')
const { weather } = useWeather('Atlanta')
const matches = computed(() => {
  const q = query.value.toLowerCase()
  return props.cities.filter(c => c.toLowerCase().includes(q))
})
const label = computed(() => `${matches.value.length} cities`)
</script>
<template>
  <input v-model="query" aria-label="Filter cities" />
  <p>{{ weather?.current?.temp ?? '--' }}° · {{ label }}</p>
  <button v-for="c in matches" :key="c" @click="emit('city-selected', c)">{{ c }}</button>
</template>
