Pillar 1 — Semantic HTML Structure

Why it matters: HTML tags are meaning signals. AI crawlers weight <article> and <h1> differently than <div class="title">. Same visual output — completely different machine-readable signal.

✗ AI-INVISIBLE

<div class="blog-post">
  <div class="title">
    My Tutorial
  </div>
  <div class="body">
    <div>Step one...</div>
    <div>Step two...</div>
  </div>
</div>

✓ GEO-READY

<article>
  <header>
    <h1>How to Handle State
        in Vue 3</h1>
    <time datetime="2026-01-15">
      Jan 2026</time>
    <address>
      By Nerando Johnson
    </address>
  </header>
  <section>
    <h2>Why Pinia Over Vuex</h2>
    <p>Pinia is the recommended...</p>
  </section>
</article>
The visual output of both code blocks is identical. That's the point. Same page, same appearance — completely different machine-readable signal. HTML tags aren't just about presentation, they're vocabulary. article, header, time, address — these are words the AI crawler knows. div class="title" is noise to a machine.

Pillar 2 — Write for Humans, Structure for AI

✗ KILLS AI DISCOVERABILITY

  • "As mentioned above, this approach…"
  • "We looked at this earlier, but…"
  • "It depends on what you're building."
  • "See the next section for details."

✓ CITABLE / SELF-CONTAINED

  • Every paragraph answers a specific question
  • Subject always explicit — no dangling pronouns
  • Direct assertions: "Pinia is the official Vue 3 state manager"
  • Definitions included inline, not referenced elsewhere

The Litmus Test:

"If someone extracted just this paragraph and read it with no context, would it still make complete sense?"

If no → rewrite it. AI will skip it.

The litmus test is the takeaway. Give the audience 15 seconds to think of a paragraph from their own writing that would fail it. The uncomfortable silence is the lesson. "As mentioned above" is the enemy. Say it again: "AI can't scroll back up."

Pillar 3 — Structured Data Markup

JSON-LD is the language of structured data. It lives in your <head> and tells AI crawlers exactly what your content is.

3 SCHEMA TYPES YOU NEED:

BlogPosting — for every article, tutorial, and blog entry

FAQPage — maps directly to how users query AI platforms

Person — establishes you as a known, citable entity

WHY JSON-LD?

  • Doesn't pollute your HTML
  • Easy to add in Astro/Vue <head>
  • Google + LLM crawlers parse it
  • Validated by Rich Results Test

[ JSON-LD in DevTools ]

JSON-LD lives in your head tag. It doesn't affect page render. It doesn't slow your site. For Astro users: one component, imported on every blog post layout. For Vue/Nuxt users: useHead() composable. Zero excuses for not having it. BlogPosting and FAQPage code examples are in the backup slides — we're going deep on Person schema live, since it pays off across every article you write.

JSON-LD — Person Schema

Why it matters: This makes you a named entity in the AI knowledge graph — not just an anonymous page author. Without it, AI engines can't confidently attribute expertise to you across multiple articles and platforms.

Add once to your portfolio homepage. It anchors your identity everywhere:

{
  "@context": "https://schema.org",
  "@type": "Person",
  "name": "Nerando Johnson",
  "alternateName": "Nerajno",
  "url": "https://developingdvlpr.com",
  "jobTitle": "Frontend Software Engineer",
  "knowsAbout": ["Vue 3", "Astro", "TypeScript", "GEO", "Web Accessibility"],
  "worksFor": { "@type": "Organization", "name": "Hygiena" },
  "sameAs": [
    "https://linkedin.com/in/nerajno",
    "https://github.com/nerajno",
    "https://bsky.app/profile/nerajno.bsky.social"
  ],
  "description": "Frontend engineer in Atlanta, GA specializing in Vue 3,
                  Astro, and web accessibility."
}

knowsAbout is your expertise signal. sameAs is your entity signal — it links your identity across platforms so AI knowledge graphs can confirm you are who you say you are.

The Person schema is the one that pays dividends across every article you've ever written. Add it once to your portfolio homepage. Every blog post that links back to your portfolio now has an entity trail. The sameAs array is the trust signal — more platforms, more confirmation. Add GitHub, LinkedIn, Bluesky, your Sessionize profile. BlogPosting and FAQPage schema follow the exact same pattern — full code in backup slides.

GEO — How does AI decide what to cite?

GEO targets AI-native engines. They don't return links — they synthesize a response and cite their sources. You win by being one of them.

KEY LEVERS:

  • Entity authority — who you are, clearly defined
  • Structured data LLM crawlers can parse
  • Self-contained, citable paragraphs

Failure mode: AI hallucinates your data, or ignores you entirely.

AI TOOLS TARGETED:

ChatGPT Search
Perplexity AI
Google AI Overviews

JSON-LD — BlogPosting Schema

Why it matters: This invisible snippet in your <head> tells AI crawlers what the page is, who wrote it, and when — the three things needed to cite you with confidence. Your readers never see it; crawlers can't ignore it.

Add this inside a <script type="application/ld+json"> tag in your page <head>:

{
  "@context": "https://schema.org",
  "@type": "BlogPosting",
  "headline": "How to Handle State Management in Vue 3 with Pinia",
  "author": {
    "@type": "Person",
    "name": "Nerando Johnson",
    "url": "https://developingdvlpr.com",
    "sameAs": [
      "https://linkedin.com/in/nerajno",
      "https://bsky.app/profile/nerajno.bsky.social"
    ]
  },
  "datePublished": "2026-01-15",
  "dateModified": "2026-02-01",
  "description": "A complete guide to Vue 3 state management using Pinia...",
  "url": "https://developingdvlpr.com/blog/vue3-pinia-state",
  "keywords": ["Vue 3", "Pinia", "state management", "frontend"]
}

author.sameAs is your entity signal — it links your identity across platforms. AI knowledge graphs use this to confirm you are who you say you are.

The sameAs array is the secret weapon. AI knowledge graphs see "Nerando Johnson on site X = Nerando Johnson on site Y" and build entity authority.

JSON-LD — FAQPage Schema

Why it matters: FAQ schema maps directly to conversational AI queries. When someone asks ChatGPT "What's the difference between Pinia and Vuex?", a well-structured FAQPage is exactly what it looks for to cite.

Each question + answer pair becomes a citable unit:

{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [{
    "@type": "Question",
    "name": "What is the difference between Pinia and Vuex in Vue 3?",
    "acceptedAnswer": {
      "@type": "Answer",
      "text": "Pinia is the official state management library for Vue 3,
               replacing Vuex. Pinia offers a simpler API, better TypeScript
               support, and native DevTools integration. Unlike Vuex,
               Pinia uses a store-per-feature pattern with no mutations."
    }
  }]
}

Each answer must be fully self-contained. Write it as a direct response — no "see our full guide."

Match questions to real queries people ask ChatGPT, Perplexity, and Google AI.

The FAQ answer must be self-contained — read just the answer, no question. Does it still make sense? If not, rewrite. The "name" field in Question schema is exactly the question people type into AI. Research it: open Perplexity, start typing your topic, see what autocompletes. That's your Q.

Building AI-Friendly FAQ Sections

SEMANTIC FAQ HTML:

<section aria-label="FAQ">
  <h2>Frequently Asked Questions</h2>

  <details>
    <summary>
      What is Vue 3 Composition API?
    </summary>
    <p>
      The Vue 3 Composition API is a set of
      additive, function-based APIs that
      allow flexible composition of logic.
      Unlike Options API, it organizes code
      by feature rather than option type.
    </p>
  </details>
</section>

QUESTION WRITING RULES:

1

Start with What, How, Why, When, Which — mirrors conversational AI queries

2

Write answers that work without reading the question first

3

Aim for 3–6 sentences per answer — citable but not skippable

The details + summary pattern is both accessible and semantic. Screen readers announce it as a disclosure widget. AI parsers see question + answer pairs. One implementation, two returns.
