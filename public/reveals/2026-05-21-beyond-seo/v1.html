Act 1

GEO Explained

Three eras. One fundamental goal.

Let's understand how we got here — and what makes GEO genuinely different.

Three Eras of Search

Same fundamental goal — get your content found — different engines, different outputs.

Era 1 — 1990s–now

SEO

Search Engine Optimization

Google, Bing • Blue links • Rankings

Era 2 — 2015–now

AEO

Answer Engine Optimization

Featured snippets • Voice • Zero-click

Era 3 — NOW

GEO

Generative Engine Optimization

ChatGPT • Perplexity • AI Overviews • Claude

A single query can hit all three simultaneously. Optimize for only one and you're invisible in the others.

These are layers, not replacements. SEO didn't die when AEO emerged. They stack.

SEO — Ranking

Targets traditional search engines. Output: a ranked list of blue links. User still has to click through.

KEY LEVERS:

  • Keyword density & semantic relevance
  • Backlinks & domain authority
  • Core Web Vitals (LCP, INP, CLS)
  • Crawlability & site architecture
  • Meta tags, canonical URLs, sitemaps

You win when: your page appears at the top of results and the user clicks through to buying-intent or local queries — where AI Overviews are rarest.

AEO — Being the Answer

Same search engines as SEO — but optimizes for the answer box that appears before any links.

KEY LEVERS:

  • Schema markup: FAQPage, HowTo, Speakable
  • Question-style headers — exact buyer phrasing
  • Direct answer in the first sentence before elaborating
  • Short paragraphs — 2–3 sentences max per answer

You win when: Google or Siri reads your content without the user ever visiting your site. Your brand gets mentioned in that first sentence.

Featured Snippet

Pulled answer — no click required

Zero-click Result

User reads the box. You may not get the visit.

[ Featured snippet screenshot ]

AEO is the middle child most developers skip entirely. Schema markup is table stakes for modern search.

GEO — Being Cited

Built for AI-native tools. These engines don't return links — they synthesize a response across multiple sources.

KEY LEVERS:

  • Entity authority — clearly defined person/brand
  • Content credibility signals
  • Structured data LLM crawlers can parse
  • Being referenced by sources AI trusts
  • Self-contained, citable paragraphs

AI TOOLS TARGETED:

  • ChatGPT Search
  • Perplexity AI
  • Google AI Overviews
  • Claude • Gemini

23× CONVERSION MULTIPLIER

0.5% of traffic from AI search → 12.1% of all signups. (Ahrefs study)

The failure mode is brutal: the AI hallucinates your data, gets facts wrong, or ignores you entirely. The win is being the source it trusts.

This is the key mindset shift for GEO vs SEO. You're building credibility on platforms you don't own. Seed mentions where AI looks first.

How AI Engines Actually Work

LLMs don't scroll like a human. They parse, chunk, and weight signals.

WHAT THEY LOOK FOR:

Semantic HTML — article, section, h1–h6 hierarchy signals content structure

JSON-LD Schema — machine-readable metadata LLM crawlers prioritize

Entity clarity — consistent, cross-referenced author identity

WHAT KILLS CITABILITY:

  • "As mentioned above…"
  • Vague pronoun references
  • Content requiring page context to parse
  • No author identity signals
  • Missing or invalid structured data

AI needs content that is self-contained, explicit, and verifiable — each paragraph should make sense extracted from context.

Think of an LLM crawler as a very fast, very literal reader who can't scroll back up. "As I mentioned above" is a broken citation.

The 3 Core Pillars of GEO

Every GEO optimization traces back to one of these three.

Semantic HTML
Structure

Proper heading hierarchy, landmark elements, meaningful markup

Explicit Content
Formatting

Self-contained paragraphs, direct answers, citable writing

Structured Data
Markup

JSON-LD schema that LLM crawlers parse and trust

These pillars also strengthen AEO and SEO — it's a rising tide that lifts all three.

Pillar 1 — Semantic HTML Structure

✗ GENERIC / AI-INVISIBLE

<div class="blog-post">
  <div class="title">
    My Tutorial
  </div>
  <div class="body">
    <div>Step one...</div>
    <div>Step two...</div>
  </div>
</div>

✓ SEMANTIC / GEO-READY

<article>
  <header>
    <h1>How to Handle State
        in Vue 3</h1>
    <time datetime="2026-01-15">
      Jan 2026</time>
    <address>
      By Nerando Johnson
    </address>
  </header>
  <section>
    <h2>Why Pinia Over Vuex</h2>
    <p>Pinia is the recommended...</p>
  </section>
</article>

Rule: Use article, section, header, address, time. Each signals meaning, not just layout. LLMs weight these heavily.

Pillar 2 — Explicit Content Formatting

✗ KILLS AI DISCOVERABILITY

  • "As mentioned above, this approach…"
  • "We looked at this earlier, but…"
  • "It depends on what you're building."
  • "See the next section for details."

✓ CITABLE / SELF-CONTAINED

  • Every paragraph answers a specific question
  • Subject always explicit — no dangling pronouns
  • Direct assertions: "Pinia is the official Vue 3 state manager"
  • Definitions included inline, not referenced elsewhere

The Litmus Test:

"If someone extracted just this paragraph and read it with no context, would it still make complete sense?"

If no → rewrite it. AI will skip it.

Pillar 3 — Structured Data Markup

JSON-LD is the language of structured data. It lives in your <head> and tells AI crawlers exactly what your content is.

3 SCHEMA TYPES YOU NEED:

BlogPosting — for every article, tutorial, and blog entry

FAQPage — maps directly to how users query AI platforms

Person — establishes you as a known, citable entity

WHY JSON-LD?

  • Doesn't pollute your HTML
  • Easy to add in Astro/Vue <head>
  • Google + LLM crawlers parse it
  • Validated by Rich Results Test

[ JSON-LD in DevTools ]

JSON-LD — BlogPosting Schema

Add this to your Astro layout or Vue <head> component:

{
  "@context": "https://schema.org",
  "@type": "BlogPosting",
  "headline": "How to Handle State Management in Vue 3 with Pinia",
  "author": {
    "@type": "Person",
    "name": "Nerando Johnson",
    "url": "https://developingdvlpr.com",
    "sameAs": [
      "https://linkedin.com/in/nerajno",
      "https://bsky.app/profile/nerajno.bsky.social"
    ]
  },
  "datePublished": "2026-01-15",
  "dateModified": "2026-02-01",
  "description": "A complete guide to Vue 3 state management using Pinia...",
  "url": "https://developingdvlpr.com/blog/vue3-pinia-state",
  "keywords": ["Vue 3", "Pinia", "state management", "frontend"]
}

author.sameAs is your entity signal — it links your identity across platforms. Don't skip it.

The sameAs array is the secret weapon. AI knowledge graphs see "Nerando Johnson on site X = Nerando Johnson on site Y" and build entity authority.

JSON-LD — FAQPage Schema

FAQs map directly to how users query AI tools. Make them explicit:

{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [{
    "@type": "Question",
    "name": "What is the difference between Pinia and Vuex in Vue 3?",
    "acceptedAnswer": {
      "@type": "Answer",
      "text": "Pinia is the official state management library for Vue 3,
               replacing Vuex. Pinia offers a simpler API, better TypeScript
               support, and native DevTools integration. Unlike Vuex,
               Pinia uses a store-per-feature pattern with no mutations."
    }
  }]
}

Each answer must be fully self-contained. Write it as a direct response to the AI query — no "see our full guide."

Match your questions to real queries people ask ChatGPT, Perplexity, and Google AI.

JSON-LD — Person Schema

The most important schema for your portfolio — makes you a citable entity:

{
  "@context": "https://schema.org",
  "@type": "Person",
  "name": "Nerando Johnson",
  "alternateName": "Nerajno",
  "url": "https://developingdvlpr.com",
  "jobTitle": "Frontend Software Engineer",
  "knowsAbout": ["Vue 3", "Astro", "TypeScript", "GEO", "Web Accessibility"],
  "worksFor": { "@type": "Organization", "name": "Hygiena" },
  "sameAs": [
    "https://linkedin.com/in/nerajno",
    "https://github.com/nerajno",
    "https://bsky.app/profile/nerajno.bsky.social"
  ],
  "description": "Frontend engineer in Atlanta, GA specializing in Vue 3,
                  Astro, and web accessibility."
}

knowsAbout is your expertise signal. AI uses this to decide when to cite you on a given topic.

✗ BEFORE (GEO-invisible)

No author signal

No schema

<script type="application/ld+json">
  {JSON.stringify({
    "@type": "BlogPosting",
    "headline": title,
    "author": {

      "url": "https://developingdvlpr.com"
    },
    "datePublished": date
  })}
</script>
<article>
  <header>
    <h1>{ title }</h1>
    <time datetime={date}>{ date }</time>
    <address>By Nerando Johnson</address>
  </header>
  <section>
    <Fragment set:html={content}/>
  </section>
</article>
The visible output barely changes. The machine-readable output changes dramatically. That's the GEO design principle: structure for machines, write for humans.

Building AI-Friendly FAQ Sections

SEMANTIC FAQ HTML:

<section aria-label="FAQ">
  <h2>Frequently Asked Questions</h2>

  <details>
    <summary>
      What is Vue 3 Composition API?
    </summary>
    <p>
      The Vue 3 Composition API is a set of
      additive, function-based APIs that
      allow flexible composition of logic.
      Unlike Options API, it organizes code
      by feature rather than option type.
    </p>
  </details>
</section>

QUESTION WRITING RULES:

1

Start with What, How, Why, When, Which — mirrors conversational AI queries

2

Write answers that work without reading the question first

3

Aim for 3–6 sentences per answer — citable but not skippable

Advanced — Entity Optimization

An entity is an unambiguous, well-defined concept the AI knowledge graph recognizes and trusts.

BUILDING YOUR ENTITY:

Consistent name + handle across all platforms (@nerajno everywhere)

Cross-referencing — your blog cites your talks; your talks mention your blog

Citations from trusted sources — Sessionize, Vue Mastery, conference sites

TOPIC CLUSTER STRATEGY:

  • 5+ articles on Vue 3 routing → you become an authority on Vue routing to AI
  • Link articles within the cluster to each other
  • Add a hub/index page that collects them all
  • Reinforce with matching JSON-LD keywords

Accessibility = GEO Foundation

WCAG 2.2 practices that double as GEO signals:

Logical heading hierarchy (1.3.1) — same signal AI uses to understand content structure

Descriptive alt text (1.1.1) — image context for AI parsing

Landmark regions (4.1.2) — main, nav, aside signal page architecture

Accessible content is explicit content. Explicit content is citable content. The three are the same work.

Done a WCAG 2.2 AA audit recently? You're already 60% of the way to Pillars 1 & 2.

This is the moment a11y advocates lean forward. Everything we do for screen reader users is exactly what AI crawlers need too. Same work, double the return.

Which Problem Are You Solving?

Match the symptom to the right lever before you open your editor.

?

Traffic dropping but rankings look fine?

?

Inbound feels different — buyers arrive more informed?
