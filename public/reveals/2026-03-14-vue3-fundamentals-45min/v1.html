What Is Vue 3?

A JavaScript framework for building user interfaces — built on top of standards you already know.

Section 1. ~7 minutes here.

Vue Explained Simply

Declarative Rendering
Describe what the UI should show based on your data — not how to manipulate the DOM.

Automatic Reactivity
Change your data. Vue updates the DOM. No selectors. No manual re-renders.

Component Model
Build UIs as a tree of reusable pieces — each owning its own logic, template, and styles.

HTML+ CSS+ JS+ No magic 

<!-- This is a complete Vue component -->
<script setup>
import { ref } from 'vue'

// Reactive state — when this changes,
// the template updates automatically
const count = ref(0)
</script>

<template>
  <button @click="count++">
    Clicked {{ count }} times
  </button>
</template>
The button example is the whole pitch. Zero DOM manipulation. Zero getElementById. Change count, UI updates. That's the contract Vue makes with you.

The Progressive Framework

Vue meets you where you are. You don't have to learn everything to start building.

Level 1 — Script Tag

Drop a CDN link into any HTML page. Add a sprinkle of Vue. No build step, no config.

Level 2 — Single-Page App

Scaffold with npm create vue@latest. Add Vue Router, Pinia. Full SPA.

Level 3 — Production Scale

Nuxt 3 for SSR, SSG, TypeScript — the full enterprise-ready stack.

No other major framework lets you go from a script tag all the way to a production SSR app using the same mental model and syntax.

Vue 3 is used in production by Alibaba, GitLab, Adobe, Grammarly, and thousands of startups.

The progressive model is a real differentiator. I've literally added Vue to a legacy HTML marketing page with one script tag. That's not a toy use case.
04 / 24

Vue vs React vs Angular

React

  • Library, not full framework
  • Choose your own routing, state
  • JSX (JS-centric syntax)
  • Huge ecosystem, more decisions

Vue 3

  • Full framework, progressive
  • Official router (Vue Router) + state (Pinia)
  • HTML-centric template syntax
  • Gentle learning curve

Angular

  • Full framework, opinionated
  • Enterprise-first design
  • TypeScript required
  • Steeper initial curve

There's no wrong answer. Vue's advantage is readability and approachability — it's the best first framework for developers who think in HTML.

Don't let the comparison paralyze you. Learn Vue. You'll understand React and Angular better having learned Vue first — the shared concepts far outweigh the differences.

Options API vs Composition API — why there are two, and which one to learn.

Section 2. ~5 minutes. This is the most common point of confusion for beginners.
05 / 24

Two Ways to Write Components

Options API — the original


<script>
export default {
  data() {
    return { count: 0 }
  },
  computed: {
    doubled() {
      return this.count * 2
    }
  },
  methods: {
    increment() {
      this.count++
    }
  },
  mounted() {
    console.log('ready')
  }
}
</script>

Composition API — Vue 3 native


<script setup>
import { ref, computed, onMounted } from 'vue'

const count = ref(0)

const doubled = computed(() => count.value * 2)

function increment() {
  count.value++
}

onMounted(() => {
  console.log('ready')
})
</script>

Both are valid. Composition API + <script setup> is the recommended path for new Vue 3 projects.

The Options API isn't dead — you'll see it in older codebases and it still works great. But everything new should use Composition API.
06 / 24

Why Composition API Wins

Logic by feature, not by type

Options API scatters feature logic across data, methods, computed, watchers. Composition API groups everything for one feature together.

Composables = reusable logic

Extract related logic into standalone functions (useCounter, useFetch) and reuse them across any component.

Better TypeScript support

The Composition API was designed with TypeScript in mind. Type inference works naturally.


// useCounter.js — reusable composable
import { ref, computed } from 'vue'

export function useCounter(initial = 0) {
  const count = ref(initial)
  const doubled = computed(() => count.value * 2)

  function increment() { count.value++ }
  function decrement() { count.value-- }
  function reset() { count.value = initial }

  return { count, doubled, increment, decrement, reset }
}

// Use in ANY component:
// const { count, increment } = useCounter(10)
Composables are the killer feature of Vue 3. Everything you could do with mixins (and more) without the naming conflicts and implicit dependencies.

Reactivity

ref, reactive, computed, watch — the engine under everything.

Section 3. ~8 minutes. This is the densest section. Take it slow.
07 / 24

ref — Reactive State


<script setup>
import { ref } from 'vue'

const count   = ref(0)       // number
const name    = ref('Nerando') // string
const isReady = ref(false)   // boolean
const tags    = ref(['vue', 'js']) // array

// In script: use .value
count.value++
console.log(name.value)

// In template: Vue auto-unwraps (no .value needed)
</script>

<template>
  <p>{{ count }} — {{ name }}</p>
  <p v-if="isReady">Ready to go!</p>
</template>

The one rule

Use .value inside <script setup>. Drop it in <template> — Vue unwraps automatically.

ref accepts anything

Primitives, objects, arrays — ref handles all of them. It's your default reactive tool.

The .value thing trips people up exactly once. After that it becomes muscle memory.
08 / 24

reactive — Object State


<script setup>
import { reactive } from 'vue'

const user = reactive({
  name: 'Nerando',
  role: 'developer',
  skills: ['Vue 3', 'TypeScript'],
  isLoggedIn: false
})

// No .value needed — access like normal JS
user.name = 'Nerajno'
user.isLoggedIn = true
user.skills.push('Nuxt')
</script>

<template>
  <p>{{ user.name }} — {{ user.role }}</p>
  <p v-if="user.isLoggedIn">Welcome back!</p>
</template>

ref vs reactive

ref wraps any value. reactive wraps objects only — no primitives.

The Vue team recommends defaulting to ref for everything. Use reactive when you have a clear group of related state.

Caveat: destructuring

Destructuring a reactive object loses reactivity. Use toRefs if you need to destructure.

When in doubt, use ref. The .value cost is worth the consistency.
09 / 24

computed — Derived State


<script setup>
import { ref, computed } from 'vue'

const items = ref([
  { id: 1, name: 'Vue 3',      done: true  },
  { id: 2, name: 'Pinia',      done: false },
  { id: 3, name: 'Nuxt 3',     done: false },
])

const filter = ref('all')

// Recalculates ONLY when items or filter changes
// Cached between renders — more efficient than a method
const filtered = computed(() => {
  if (filter.value === 'done')    return items.value.filter(i => i.done)
  if (filter.value === 'pending') return items.value.filter(i => !i.done)
  return items.value
})

const doneCount = computed(() => items.value.filter(i => i.done).length)
</script>

Computed properties are cached — they only recalculate when their reactive dependencies change. If a value can be derived, make it computed.

The caching is the key value prop of computed. A method would recalculate on every render. Computed only runs when it needs to.
10 / 24

watch & watchEffect

watch — specific


import { ref, watch } from 'vue'

const query = ref('')

// Runs when query changes
// Gets old + new value
watch(query, (newVal, oldVal) => {
  fetchResults(newVal)
})

// Watch multiple sources
watch(
  [query, filter],
  ([q, f]) => search(q, f)
)

watchEffect — auto-track


import { ref, watchEffect } from 'vue'

const count = ref(0)
const msg   = ref('')

// Runs immediately,
// auto-tracks ALL reactive
// deps used inside
watchEffect(() => {
  msg.value =
    `Count: ${count.value}`
})

When to use what


watch
  ✓ Need old + new value
  ✓ Lazy (only on change)
  ✓ Specific source

watchEffect
  ✓ Run immediately
  ✓ Multiple auto deps
  ✓ Simpler syntax
My rule of thumb: watch for API calls and things where old/new comparison matters. watchEffect for syncing reactive state into side effects.

Single-File Components


<!-- TaskCard.vue -->

<script setup>
import { ref } from 'vue'

const props = defineProps({
  task: { type: Object, required: true }
})

const emit = defineEmits(['complete'])
const isExpanded = ref(false)
</script>

<template>
  <div
    class="card"
    :class="{ done: task.completed }"
  >
    <h3 @click="isExpanded = !isExpanded">
      {{ task.title }}
    </h3>
    <p v-if="isExpanded">{{ task.description }}</p>
    <button
      @click="emit('complete', task.id)"
      :disabled="task.completed"
    >Complete</button>
  </div>
</template>

<style scoped>
.card { padding: 1rem; border-radius: 8px; }
.done { opacity: 0.5; text-decoration: line-through; }
</style>

script setup

Logic lives here. Reactive state, props declaration, emit declaration, methods.

template

HTML + Vue directives. Everything here reacts to the script automatically.

style scoped

CSS that applies only to this component. Vue handles the scoping — no class collisions.

All in one .vue file. Portable. Self-contained. Testable.

This one component uses props, emits, local ref state, two directives, scoped styles, and conditional rendering. That's a real component pattern right there.
12 / 24

Props Down · Events Up

Props carry data from parent → child. They're read-only inside the child.


<!-- Parent: pass data down -->
<TaskCard
  :task="currentTask"
  :show-details="true"
  @complete="handleComplete"
  @delete="handleDelete"
/>

Events carry information from child → parent. The child emits, the parent listens.


<!-- Child: define what it receives
     and what it can send back -->
<script setup>
const props = defineProps({
  task: {
    type: Object,
    required: true
  },
  showDetails: {
    type: Boolean,
    default: false
  }
})

const emit = defineEmits([
  'complete',
  'delete'
])
</script>

This pattern keeps data flow predictable. One direction down, one direction up. Easy to debug.

Props down, events up is the law of component communication in Vue. If you internalize nothing else from this section, internalize that.

The Core Directives

v-bind ( : )

Bind attribute to reactive data
:href="url" :class="{ active }" :style="obj"

v-on ( @ )

Handle DOM events
@click="fn" @submit.prevent @keyup.enter

v-model

Two-way binding on inputs
v-model="searchQuery" — works on text, select, checkbox, radio

v-if / v-else / v-show

v-if removes from DOM. v-show toggles CSS display. Use v-show for frequent toggling.

v-for + :key

Render lists from arrays. Always include :key for efficient updates — use a unique id, not the array index when possible.

These five patterns cover 90%+ of what you'll do in templates day to day.
14 / 24

All Five, One Component


<script setup>
import { ref, computed } from 'vue'

const newSkill = ref('')
const skills   = ref(['Vue 3', 'TypeScript', 'Nuxt'])
const filter   = ref('all')

const visible = computed(() =>
  filter.value === 'vue'
    ? skills.value.filter(s => s.includes('Vue'))
    : skills.value
)

function addSkill() {
  if (newSkill.value.trim()) {
    skills.value.push(newSkill.value.trim())
    newSkill.value = ''
  }
}
</script>

<template>
  <input v-model="newSkill" @keyup.enter="addSkill" placeholder="Add a skill" />
  <button @click="addSkill">Add</button>

  <select v-model="filter">
    <option value="all">All</option>
    <option value="vue">Vue only</option>
  </select>

  <ul v-if="visible.length">
    <li v-for="skill in visible" :key="skill">{{ skill }}</li>
  </ul>
  <p v-else>No skills match.</p>
</template>
v-model input, @keyup.enter, @click, v-model on select, v-if, v-else, v-for, :key, computed — a real functional component, not a toy.

Mini Demo: Todo App Architecture

App.vue

Single source of truth. All todo state lives here. Passes data down, listens for events up.

TodoInput.vue

Owns its own local input state. Emits 'add' with the text when submitted.

TodoItem.vue

Pure presentational. Receives a todo prop. Emits 'toggle' and 'delete'.

TodoFilter.vue

Receives active filter as prop. Emits 'change' when a tab is clicked.


<!-- App.vue — the full state layer -->
<script setup>
import { ref, computed } from 'vue'

const todos       = ref([])
const activeFilter = ref('all')

const filtered = computed(() => {
  if (activeFilter.value === 'active')
    return todos.value.filter(t => !t.completed)
  if (activeFilter.value === 'done')
    return todos.value.filter(t => t.completed)
  return todos.value
})

function addTodo(text) {
  todos.value.push({ id: Date.now(), text, completed: false })
}
function toggle(id) {
  const t = todos.value.find(t => t.id === id)
  if (t) t.completed = !t.completed
}
function remove(id) {
  todos.value = todos.value.filter(t => t.id !== id)
}
</script>

The Vue Ecosystem

OFFICIAL

Vue Router

Multi-page navigation. File-based routes in Nuxt.

Pinia

State management. Simpler Vuex — the official replacement.

META-FRAMEWORK

Your Learning Path

Vue 3 Fundamentals You are here — this series. Build the todo app.
Vue Router Add multiple pages to your app. Understand history mode, dynamic routes.
Pinia Shared state across components. Replaces Vuex. Much simpler.
Composables Extract and reuse logic. The Vue 3 superpower you want to learn early.
Nuxt 3 When you're ready to go to production with SSR/SSG.
TypeScript + Vue Add type safety. Easier than it sounds once you know the framework.
The order matters. Don't jump to Nuxt before you're comfortable with components and reactivity. That's how people get stuck.
